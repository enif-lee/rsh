# TCP batch candidate: functional validation (2026-10-30)

This is an unmeasured candidate, not evidence of SSH parity or of performance
without regressions. Performance runs stopped before any jobs started because
host headroom never passed the preflight. The user chose to keep the current
host load and continue functional checks only. Existing published benchmark
numbers are unchanged.

## Change

The server passes an already prepared TCP packet batch to `TcpSide::send_batch`.
For two or more packets, `write_batch` writes up to eight length headers and
payloads with one vectored write. This adds no gathering delay. Empty batches
return immediately; single packets use the existing `send` path.

The two-byte frame format, encryption, protocol version, pacing, credit/window
policy, and UDP send path are unchanged. A partial write keeps only the unsent
suffix; the existing 1 MiB queued-length bound and broken-connection handling
still apply. The bound is on length, not retained `Vec` capacity or process RSS.

Eight new tests cover short header/payload writes, EINTR, repeated WouldBlock,
old backlog ordering, empty and maximum-length frames, rejected oversized
frames, write-zero, and an empty batch leaving queued data untouched. A real
socket test forces backpressure with small socket buffers, then drains 256
uniquely identified frames through the TCP service loop and checks exact order
and an empty final backlog. The fake writer also checks that the writable path
allocates no backlog and uses fewer write calls than packets; this is not an
end-to-end performance measurement.

## Failures and limits

- The first Alpine parallel run failed `attach_in_the_middle_of_an_escape_sequence`
  (Detached instead of Exited) and `ctrl_c_drops_a_large_unacked_backlog`
  (five-second flood wait). The same candidate passed both in the serial session
  run. The baseline parallel session target passed all 25 in a separate run
  ([log](data/tcp-batch-20261030/baseline-linux-alpine-sessions.log)). Host timing
  is a plausible explanation, not a proven cause; a clean parallel Linux result
  under controlled load remains outstanding.
- With tmux installed, the candidate and baseline both fail the Alpine tmux check
  at `tests/binary_cli.rs:323`. Both reproductions are retained
  ([candidate](data/tcp-batch-20261030/linux-alpine-serial.log),
  [baseline](data/tcp-batch-20261030/baseline-linux-alpine-tmux.log)). The candidate's
  four binary checks pass in the `rsh-bench` runtime. The Alpine failure is not
  claimed fixed.
- In the `rsh-bench` runtime, the lossy UDP session test fails at
  `tests/session.rs:408`: no initial number 1 is found. The baseline exact test
  reproduces the same failure in the same runtime
  ([log](data/tcp-batch-20261030/baseline-linux-benchmark-image-lossy.log)). It is
  a pre-existing failing case in that environment, not a resolved issue.
- Native tests unset `NO_COLOR` only in the test subprocess. The existing badge
  color assertion also fails on baseline with `NO_COLOR=1`
  ([log](data/tcp-batch-20261030/baseline-macos-badge.log)); no product behavior
  or user environment was changed to make it pass.
- The two ignored library tests are the published-release integrity check and
  the terminal performance microbenchmark. They were not run. No test assertion
  or timeout was relaxed.

## Before promotion

A controlled baseline/candidate comparison is still required for average FPS,
1%/5% low FPS, frame age/correctness, network traffic, CPU/RSS, input latency,
throughput, reconnect and changing links. It must include loss, high RTT, low
bandwidth and the moving profile. Published runs use four parallel jobs and
three iterations (session memory once); development uses one iteration and
eight parallel jobs. Functional passes and fewer writer calls do not establish
improved FPS, SSH parity, or resource non-regression. The PR must stay a draft
until the performance acceptance criteria and outstanding Linux checks are met.

## Review disposition

The reviewer identified an unnecessary flush on an empty batch. An early return
and a test preserving the existing backlog without writer calls address it;
single-packet sends also retain the previous path. The final source review found
no additional blocking defect. Source hashes, eight batch-test passes and the
baseline reproductions were independently checked. Report-link and missing-log
findings were accepted and corrected. No defect finding was rejected. Linux
failure causes and end-to-end performance remain unverified as described above.
